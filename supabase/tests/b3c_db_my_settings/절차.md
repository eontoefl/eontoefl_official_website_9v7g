# 계약 3C-DB — "본인 설정" 함수 다섯의 시험 절차 (브레인방용)

(3차 판 — 2차 판 `aabe988`을 시험 프로젝트에서 실행한 결과 8-6에서 걸린 것을 고쳤다: `my_marketing_consent_set`의 인자를 `boolean`에서 `jsonb`로 — PostgREST가 JSON 글자 `"true"`·`"yes"`·`"t"`와 숫자 `1`을 참으로 바꿔 넘겼다. **이 함수의 인자 형과 본문 md5가 바뀌었으므로 2차 판으로 적용한 함수는 2차 판의 되돌리기 SQL로 되돌린 뒤에 이 판을 처음부터 잰다.**)

(2차 판 — 실행 전 검토의 네 가지를 반영했다: 합성 계정의 계정 번호 + 로그인 이메일 대조, 비밀번호 열 원문을 내보내지 않음, 읽기에서 `utm_data` 안쪽과 `answered_at`을 좁힘, 되돌리기의 기준이 다르면 멈춤.)

**이 폴더의 SQL·도구와 마이그레이션·되돌리기 SQL은 한 번도 실행되지 않았다.** 작업방은 파일만 썼다. SQL은 실행도 문법 확인도 하지 못했고, `settings_matrix.mjs`는 가짜 응답(네트워크 없음)으로만 돌려 봤다. 가짜 응답은 실제 동작을 대신하지 않는다.

대상은 **시험 프로젝트 `hmncdheiwqwekdbtijar`뿐**이다. 운영(`qpqjevecjejvbeuogtbx`)에는 아무것도 보내지 않는다.

3-0의 절차(`../b3_0_my_profile/절차.md`)와 같은 틀이다. **다른 점은 하나다: 이 계약의 함수 셋은 회원 행을 고친다.** 그래서 "앞뒤 불변" 대신 "바뀐 열이 정확히 기대한 열뿐인가"를 보고(`rows-effect`), 재기마다 합성 회원의 설정 열을 처음 값으로 되돌린다(`fixtures_reset.sql`).

- SQL 통로는 한 요청의 여러 문장을 같은 접속으로 보내고 마지막 문장의 결과를 돌려준다. 결과가 jsonb 한 칸인 SQL은 그 결과를 파일로 저장해 도구에 넘긴다(`[{"result":{…}}]` 모양 그대로 받는다).
- **무엇인가를 바꾸는 시험용 SQL**(`fixtures_*`·`answers_variant`·`hook_*`·`maint_*`·`session_*`)은 같은 요청의 맨 앞에 `set b3c.test_project_ref = 'hmncdheiwqwekdbtijar';`와 그 파일이 받는 값들의 `set` 줄이 있어야 돈다. **그 값은 실제 연결 대상을 증명하지 못한다** — 실행 직전에 SQL 통로가 가리키는 프로젝트의 ref를 직접 확인한다.
- `set` 줄은 손으로 옮겨 적지 않는다: `node settings_matrix.mjs --phase set-lines --for <무엇> …`이 저장해 둔 파일에서 글자 그대로 만들어 준다(요청 0).
- 이 SQL들은 조건에 맞는 행이 정확한 수가 아니면 예외로 끝나 **전체가 되돌아간다.**

## 함수가 하는 일 (마이그레이션이 만드는 것)

전부 `POST /rest/v1/rpc/<이름>`, `authenticated`만 실행, 회원번호·이메일을 받지 않는다(살아 있는 로그인 기록의 회원 대응으로 본인 한 행만).

| 함수 | 본문 | `ok`일 때의 응답 | 고치는 열 |
|---|---|---|---|
| `my_settings` | `{}` | `{state, settings:{intro_book_track, intro_book_track_supported, marketing_consent, marketing_consent_at}}` | 없음 |
| `my_book_answers` | `{}` | `{state, answers}` — `answers`는 `null`(열이 SQL NULL) 또는 열두 항목 + `answered_at`. 저장된 값이 객체가 아니거나 열두 항목이 빠졌거나 형이 틀리면 `{"state":"answers_corrupt"}`. **`utm_data`는 정해 둔 utm 키 다섯 가운데 있는 것만** 돌려주고 그 안의 값이 하나라도 글자가 아니면 파손. **`answered_at`은 시각으로 읽히는 글자일 때만** 그 글자를 돌려주고(없으면 `null`), 그 밖의 글자는 파손 | 없음 |
| `my_intro_track_set` | `{"p_track":"regular"\|"australia"}` | `{state, intro_book_track}` | `intro_book_track` |
| `my_marketing_consent_set`(인자의 형은 `jsonb` — **JSON `true`만** 받는다. 글자 `"true"`·숫자 `1`·널·거짓·배열·객체는 거절) | `{"p_consent":true}` | `{state, marketing_consent, marketing_consent_at}` | `marketing_consent`·`marketing_consent_at` |
| `my_book_answers_hold` | `{"p_answers":{열두 항목}}` | `{state, answers}`(저장된 것: 열두 항목 + 서버가 붙인 `answered_at`) | `pending_book_request` |

`200`으로 돌려주는 모든 상태에 `Cache-Control: private, no-store`.

## 합성 계정과 자격

3-0과 같은 8계정이다. **`accounts.json`에는 계정마다 정확한 계정 번호와, 계정을 만들 때 받은 로그인 이메일(`auth.users.email`)을 함께 적는다**:

```json
{"a": {"id": "<계정 번호>", "email": "<로그인 이메일>"}, "b": {…}, "n": {…}, "g": {…}, "gm": {…}, "blk": {…}, "wd": {…}, "bw": {…}}
```

- **로그인 이메일에는 합성 표식 `zzb3c`가 들어 있어야 한다**(이름 부분이든 도메인이든 — 예: `zzb3c_a_<무작위>@…`). 여덟 이메일은 서로 달라야 한다. 로그인 서버가 어떤 도메인을 받는지는 작업방이 확인하지 못했다 — 표식을 이름 부분에 두면 도메인과 무관하다.
- `fixtures_up.sql`·`fixtures_down.sql`·`maint_on.sql`은 **`auth.users`에서 그 계정 번호의 이메일이 넘겨받은 이메일과 같고(대소문자만 무시) 표식 `zzb3c`를 가졌음**을 확인한 뒤에만 쓴다. 하나라도 다르면 아무것도 쓰기 전에 전체가 멈춘다("이번에 만든 합성 계정인가"를 계정 번호만으로 믿지 않는다). 관리자 명부에 넣는 g·gm, 점검 예외에 넣는 a, 지울 때의 대응 6·명부 2가 전부 이 대조를 지난다.
- 회원 행의 이메일은 로그인 이메일과 다른 값이다: `zzb3c_<이름>@member.zzb3c.invalid`(회원 표에만 들어간다 — 로그인 서버를 거치지 않는다).

| 계정 | 상태 | 종류 | 동의 | 보관 답변 | 도구의 자격 이름 |
|---|---|---|---|---|---|
| `a` | 정상 | `regular` | `true`(시각 있음) | 지금 형식 | `member_a` (+ `a_expire`·`a_logout`·`a_old`) |
| `b` | 정상 | `australia` | `false` | **SQL NULL**(보관 없음) | `member_b` |
| `n` | 회원 대응 없음(함정 행만) | — | — | — | `no_map` |
| `g` | 관리자, 회원 대응 없음 | — | — | — | `admin_g_pre`·`admin_g_post` |
| `gm` | 관리자 + 회원 | **`zzb3c_old_track`**(지원하지 않는 값) | **NULL** | **옛 형식**(열두 항목 + 그 밖의 키 둘, `answered_at` 없음) | `admin_gm_pre`·`admin_gm_post` |
| `blk` / `wd` / `bw` | 차단 / 탈퇴 처리 중 / 둘 다 | 값 있음 | 값 있음 | 지금 형식 | `blocked` / `withdrawing` / `blocked_withdrawing` |
| (함정 행 `trap`) | 회원번호 = 계정 `n`의 **로그인 계정 번호**, 대응 없음 | `australia` | `true` | 지금 형식 | — (누구의 응답에도 나오면 안 되고 누구의 요청으로도 고쳐지면 안 된다) |

- 보관 답변의 글자 값에는 회원마다 다른 표식(`zzb3c-…-<이름>`)이 있다 — 남의 답변이 응답에 실리면 잡힌다.
- 환경 변수: `B3C_URL`(정확히 `https://hmncdheiwqwekdbtijar.supabase.co`), `B3C_ANON_KEY`·`B3C_SERVICE_KEY`, `B3C_JWT_A`·`_B`·`_N`·`_BLK`·`_WD`·`_BW`, `B3C_JWT_G1`/`_G2`·`B3C_JWT_GM1`/`_GM2`(6자리 전 aal1 / 후 aal2), `B3C_JWT_A_EXP`·`_A_OUT`·`_A_OLD`(A의 다른 로그인 셋).
- 로그인 순서(2-나-2b에서 확인됨): **G·GM은 먼저 6자리 확인까지 끝내 aal2 자격을 받고, 그 뒤에 따로 새로 로그인해 aal1 자격을 받는다.**
- **자격 원문은 환경 변수에만 둔다. 파일에 쓰지 않는다**(3-0의 시험에서 60분을 기다리는 동안 임시 파일에 적은 것이 절차 위반으로 기록됐다). `B3C_JWT_A_OLD`의 한 쌍을 기다리는 동안 실행 환경이 끊기면 **그 한 쌍을 처음부터 다시 잰다.**

## 도구의 단계와 판정

| `--phase` | 무엇 | 요청 | 회원 행을 고치는가 |
|---|---|---|---|
| `start-check --fingerprint <P0>` | 시작 지문이 이번 시작 기준과 같은가(함수 다섯 없음 · `my_profile`이 3-0의 끝 상태 · 설정·점검·예외·합성 행 없음). 다르면 종료 값 3 | 0 | — |
| `end-check --p-start --p-end --g-start --g-end --leftover [--s-start --s-end]` | 끝 확인을 한 표로(14단계) | 0 | — |
| `plan --state <상태>` | 그 상태의 칸과 기대값 | 0 | — |
| `sessions-sql` | 지금 자격들의 로그인 기록을 읽는 SQL | 0 | — |
| `absent` | 적용 전 기준: 다섯 RPC가 "등록되지 않은 함수"(지문에 함수 없음과 **둘 다**) | 15 | 아니오 |
| `matrix --state <상태> --rows <직전 스냅숏>` | 함수 5 × 자격 12 × `POST`·`GET`·`HEAD` + 쓰기 뒤 다시 읽기 + 인자를 붙여 남을 겨냥한 요청 8 | 212 | **예**(통과하는 정상 회원의 본인 행) |
| `effect --step <단계> --rows <직전 스냅숏>` | 쓰기의 효과: `track`·`consent`·`hold`·`bounds`·`rejects`·`coercion`·`race` | 3~83 | 예(`rejects`는 아니오) |
| `variants --round <1~6> --variant <answers_variant 결과>` | 저장된 답변의 모양별 읽기 | 6 | 아니오 |
| `revoked --kind … --step … --rows <직전 스냅숏>` | 로그인 기록 만료·로그아웃·JWT 만료(다섯 함수 전부) | 7 | `pre`·`restored`만 예 |
| `rows-effect --before --after --result` | 쓰기 단계의 앞뒤 스냅숏과 그 단계의 결과를 견준다 | 0 | — |
| `compare --a --b [--ignore 키,…]` | 지문 결과 둘을 견준다(`read_at`은 늘 뺀다) | 0 | — |
| `set-lines --for <무엇> …` / `body-md5` | SQL 앞의 `set` 줄 / 함수 다섯의 본문 md5. **`--for rollback`은 지문의 본문 md5가 파일에서 계산한 값과 다르면 줄을 만들지 않고 멈춘다(종료 값 3)** | 0 | — |

- 도구는 상태를 스스로 알지 못한다 — **재기 직전에** `fingerprint.sql`(→ `--fingerprint`), 3-4의 SQL(→ `--sessions-alive`), `rows_md5.sql`(→ `--rows`)을 떠서 넘긴다(30분보다 오래된 파일은 받지 않는다). 맞지 않으면 요청을 보내지 않는다(종료 값 2 또는 3).
- **읽기의 기대값은 `--rows`의 "지금 저장된 값"이다.** `matrix`는 시작 상태가 합성 자료의 처음 값이 아니면(지원하지 않는 종류·동의 참/거짓/NULL·답변 있음/없음/옛 형식이 다 있어야 한다) 요청 0으로 멈춘다(종료 값 3) — `fixtures_reset.sql`을 먼저 한다.
- 판정(칸마다): **통과** / **기대와 다름** / **미확인**(네트워크 오류·시간 초과·429·기대하지 않은 5xx).
  - `ok` 칸: 응답의 키 집합이 **정확히** 같고(`settings`는 넷, `answers`는 열두 항목 + `answered_at`), 값이 저장된 값(읽기)·보낸 값(쓰기)과 같고, `Cache-Control`이 `private, no-store`.
  - `blocked`·`withdrawal_pending`·`no_member`·`answers_corrupt` 칸: 응답의 키가 **정확히 `state` 하나**.
  - 모든 칸: 금지 키(`password`·`role`·`level`·`blocked`·`withdrawal_*`·`id`·`name`·`email`·`auth_user_id`·`member_id`·`pending_book_request` 등)가 없고, 본문 글자 전체에 `password`라는 글자와 **금지 값**이 없다. 금지 값 = 합성 회원 전원(함정 행 포함)의 회원번호·이름·별명·이메일·전화, 옛 비밀번호 열의 표식, 탈퇴 사유 표식, 로그인 계정 번호, **남의 보관 답변의 표식**, 옛 형식의 "그 밖의 키". 이 함수들은 본인의 이름·이메일도 돌려주지 않는다 — `ok` 칸에서 허용하는 것은 본인의 보관 답변(열두 항목 + `answered_at`) 글자뿐이다.
  - 비밀번호 열의 값은 **원문 없이** 찾는다(원문은 어느 파일에도 없다): 합성 값의 고정 접두사 `zzb3c-pwcol-`가 응답 글자에 없는가 + 응답의 글자 값 하나하나의 sha256이 `expect.json`의 `password_column.sha256`과 같지 않은가.
  - 인자를 붙여 남을 겨냥한 요청: **통과로 세는 거절은 둘뿐이다 — 함수를 찾지 못함(`404`·`PGRST202`) 또는 점검 거절(`503`·`PT503`).** 값이 왔으면(`state`·`settings`·`answers`) 기대와 다름, 2xx거나 **예상한 거절 코드가 아닌 4xx면 미확인**이다(무엇이 거절했는지 모르는 것을 통과로 세지 않는다). 관측한 상태·코드는 `observed`에 적힌다. 남의 행이 고쳐지지 않았음은 `rows-effect`가 본다.
  - `GET`: 함수까지 도달한 로그인 자격은 `405`·`code` `PT405`(3-0의 시험에서 이 PostgREST는 `VOLATILE` 선언만으로 `GET`을 막지 않았다 — 함수 안의 확인이 막는다). 쓰기 함수의 `GET`·`HEAD`는 인자를 주소에 붙여 보낸다(붙이지 않으면 함수를 찾지 못해 404가 된다).
- **`rows-effect`가 보는 것**: 합성 회원마다 바뀐 열(열별 md5)이 그 단계의 결과가 적어 둔 `expected_effects`와 **정확히** 같은가(다른 열이 하나라도 바뀌면 다름), 저장된 값이 응답과 같은가, 동의 시각이 **앞뒤 스냅숏의 DB 시각 사이**인가, 합성 회원이 아닌 회원 행 전체의 md5·전체 회원 수·대응표·관리자 명부가 그대로인가. 이것은 **그 단계 전체를 사이에 둔 앞뒤**의 대조다(사이에 고쳐졌다가 되돌려진 것은 보이지 않는다). 요청 하나의 효과는 `effect` 단계(요청 2~3건)의 결과로 본다.
- 종료 값: 0 = 전부 통과 / 1 = 기대와 다름 또는 미확인 / 2 = 요청 전에 멈춤 / 3 = 기준선 불일치.
- 결과 파일에는 응답 본문과 열쇠·자격이 적히지 않는다. 적히는 값은 셋뿐이다: 도구가 보낸 종류 값, 서버가 돌려준 동의 시각·`answered_at`, 보관 답변의 sha256.

## 중단 규칙

- 대상이 `hmncdheiwqwekdbtijar`가 아니거나 확인할 수 없으면 아무것도 쓰지 않고 멈춘다.
- **시작 지문이 기대와 다르면 시작하지 않는다. 다른 조각(3B 등)의 행·설정을 이 절차가 원복하지 않는다**(0단계).
- 어느 단계든 기대와 다르면 다음 단계로 넘어가지 않는다. 무엇이 왔는지 기록한다.

- `session_restore.sql`이 멈추면 그 로그인 기록을 더 건드리지 않고 사람에게 넘긴다.
- **되돌리기의 기준이 다르면 스스로 맞추지 않는다.** `set-lines --for rollback`이 종료 값 3으로 멈추면(지문의 함수 본문 md5가 마이그레이션 파일에서 계산한 값과 다르다) 되돌리기 SQL을 돌리지 않고 사람에게 넘긴다. 도구는 DB에서 읽은 값을 견줄 값으로 대신 넘기지 않는다.

- 8-5의 **JSON 글자가 아닌 값** 칸(3차): `p_track`에 참·거짓·배열·객체를 넣는다. PostgREST가 글자로 바꿔 넘겨도(참 → `'true'`, 배열 → `'["regular"]'`) 허용 값 둘이 될 수 없으므로 기대는 `400`·`PT400`·`invalid_track`이다(숫자 `123`은 2차 실행에서 이미 그렇게 거절됐다). `p_answers`에는 올바른 한 벌을 **글자로 쓴 것**을 넣는다 — 객체로 풀어 받으면 안 되고 `not_object`로 거절돼야 한다. 이 다섯 칸은 다른 거절(4xx)이 오면 **미확인**(누가 거절했는지 모른다), 받아들여지면 기대와 다름이다.
- 8-4·8-5의 **전체 바이트 경계**(16,384 받음·16,385 거절)는 도구가 "PostgreSQL이 `jsonb`를 글자로 바꾼 것"의 바이트 수를 스스로 계산해 만든 값이다(콜론·쉼표 뒤에 빈칸 하나씩). 그 계산이 DB와 다르면 이 두 칸만 어긋난다 — 그때는 64바이트 떨어진 칸(16,320 받음·16,448 거절)이 맞는지를 보고, 어긋난 바이트 수를 기록해 돌려준다(함수의 결함인지 도구의 계산인지를 가르는 것은 사람이다).
- 글자 수는 **코드 포인트**로 센다(SQL의 `char_length`). 4바이트 글자 200자는 브라우저의 `length`(UTF-16 단위)로는 400이지만 서버는 200자로 받는다.
- 상세의 공백: 서버는 화면의 `trim()`이 지우는 것과 같은 공백 글자 목록(탭·줄바꿈·빈칸·U+00A0·U+3000 등)으로 "공백만인가"를 본다. 앞뒤에 공백이 있어도 가운데 글자가 있으면 받고, **받은 그대로 저장한다**(서버가 다듬지 않는다).
- 8-7에서 어느 쪽이 남는지는 관측일 뿐이다. 이 시험은 **"남은 것이 둘 중 한 벌 전체다(항목이 섞이지 않는다)"**만 본다. "오래된 창의 덮어쓰기를 막는다"는 뜻이 아니다.
- `rows-effect`가 "앞뒤 스냅숏이 그 단계를 사이에 두지 않았다"고 하면 스냅숏의 순서가 틀린 것이다(뜬 순서를 다시 본다).

## 11단계 — 되돌리기

| 순서 | 보낼 요청 | 기대 | 변화 |
|---|---|---|---|
| 11-1 | **대상을 다시 확인**하고, `node settings_matrix.mjs --phase set-lines --for rollback --fingerprint P1.json`의 줄(`set b3c.applied = '{…}';`) + 되돌리기 SQL 전체 | 오류 없음. `b3c 되돌리기 중단: …`이 나오면 아무것도 지우지 않은 것이다 — 문구를 기록하고 멈춘다 | 함수 다섯 사라짐 |
| 11-2 | SQL: `notify pgrst, 'reload schema';` → `fingerprint.sql` → **P11**, `../b2n2b_storage_policies/fingerprint.sql` → **G11** | P11: 다섯 모두 `named_count` 0 | 없음 |
| 11-3 | `… --phase compare --a PA.json --b P11.json` 그리고 `… --phase compare --a G0.json --b G11.json` (`sessions`만 다르면 `--ignore sessions`) | 둘 다 종료 값 0 — **되돌리면 지문이 적용 전과 같다** | 없음 |
| 11-4 | `… --phase absent --expect expect.json --fingerprint P11.json --out absent-after.json` | 종료 값 0 | 없음 |

- 되돌리기 SQL은 함수만 지운다. **그동안 함수가 고친 합성 회원의 설정 값은 그대로 남는다**(지문은 회원 행의 값을 보지 않는다 — 값은 14단계에서 행째로 지운다).
- **`set-lines --for rollback`은 지문의 함수 본문 md5가 마이그레이션 파일에서 계산한 값과 다르면 줄을 만들지 않고 멈춘다(종료 값 3).** DB에서 읽은 값을 견줄 값으로 대신 넘기지 않는다. 그때는 되돌리기 SQL을 돌리지 않고 멈춘 문구(어느 함수의 어느 값이 다른지)를 기록해 사람에게 넘긴다 — 누가 함수를 바꿨는지, SQL 통로가 본문 글자를 바꿔 보냈는지를 사람이 확인한다.
- 되돌리기에 넘기는 지문은 **실제로 확보한 것뿐**이다: 처음 적용한 함수는 P1(6-2), 다시 적용한 함수는 P12(12-1). 그 지문을 확보하지 못했으면 되돌리기 SQL을 돌리지 않는다(위 "중간에 멈췄을 때").

## 이 절차가 확인하지 않는 것

- **로그인 기록 만료 시험의 계정 대조.** `session_expire.sql`·`session_restore.sql`은 3-0 그대로 로그인 기록 번호 + 계정 번호 + 바꾸기 전 값으로 한 행을 고른다(로그인 이메일 대조는 더하지 않았다). `maint_off.sql`도 이메일 대조를 하지 않는다 — `maint_on.sql`이 대조를 지나 넣은 한 행 (311, A)이 그대로일 때만 지운다.
- **회원 표의 보호.** 회원 표는 여전히 공개 키·로그인 역할에 직접 열려 있다. 이 함수들이 통과해도 회원 표가 보호된다는 뜻이 아니다.
- **화면 연결**(3C-2·3C-3), 내 정보 고치기·별명 확인·보관 답변 지우기(이 조각이 만들지 않는다).
- **브라우저가 쓰는 실제 배포 경로에서의 `Cache-Control`.** 도구는 API 주소에 직접 보낸 요청의 머리글만 본다.
- **회원 표가 잠긴 뒤(전환)의 동작**, 특히 `FORCE ROW LEVEL SECURITY`.
- **오래된 창의 덮어쓰기.** 8-7은 항목이 섞이지 않는지만 본다.
- **재전송.** 응답을 받지 못한 동의 요청이 다시 오면 시각이 다시 쓰인다(계약대로 — 가리는 식별값이 없다).
- **요청 하나하나의 "다른 열 불변"**은 8단계의 몇 건으로만 본다. 대조표(212칸)는 전체의 앞뒤다.
- **쓰기 도중의 차단**(행을 잠그는 동안 관리자가 그 회원을 차단하는 경우 등 동시성), 응답 시간.
- 책 연결·대리 자격으로 이 RPC를 부르는 경우, 접근 등록부에 대상으로 적힌 회원의 로그인, 예외 명단의 만료.
- 운영에서의 동작. 이 함수들은 작업 브랜치와 시험 프로젝트에만 있다.
