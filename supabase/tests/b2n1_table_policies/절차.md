### 판정법 (스크립트와 예행이 같은 규칙을 쓴다)
| 동작 | 허용으로 세는 조건 | 거절로 세는 조건 |
|---|---|---|
| 읽기 | 돌려받은 행의 **식별값**이 기대 집합과 같음(두 행 / 자기 행 하나). 행 수만으로 판정하지 않는다 | 돌려받은 식별값이 빈 집합(또는 42501) |
| 넣기 | 2xx이고 넣기 키가 저장돼 있으며 다른 행은 그대로 | 오류 코드가 **42501**이고 저장값 변화 0. 중복 키·필수 열 누락·제약 위반 등 다른 오류는 `error`(거절로 세지 않고 기대와 다름으로 남는다) |
| 수정 | 돌려받은 행 1개, 대상 행의 저장값이 `changed`, 대조군 행 그대로 | (돌려받은 행 0개 또는 42501)이고 대상·대조군 저장값 변화 0 |
| 삭제 | 돌려받은 행 1개, 대상 행이 없어짐, 대조군 행 그대로 | (돌려받은 행 0개 또는 42501)이고 변화 0 |
- 시험 전 확인: 요청마다 저장값을 먼저 읽어 **대상 행·대조군 행이 처음 값으로 있고 넣기 키가 비어 있음**을 본다. 아니면 그 판정은 `precondition_failed`(기대와 다름)다. 쓰기 요청 뒤에는 합성 행을 같은 처음 값으로 되돌린 다음에 다음 요청을 보낸다.
- 넣기 입력의 유효성: 표마다 시작할 때 같은 입력을 서비스 열쇠로 넣어 보고(`insert_payload_valid`) 되돌린다. 들어가지 않으면 스크립트가 멈춘다.
- 넣기 요청은 `Prefer: return=minimal`로 보낸다(넣은 행을 돌려받으려면 읽기 규칙도 통과해야 해서, 읽기 권한이 없는 역할의 정당한 넣기가 42501로 보일 수 있다).
