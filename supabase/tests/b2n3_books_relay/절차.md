# 계약 2-나-3 (나) — 책 PDF 전달 방식 실측 절차 (브레인방용)

**이 폴더의 도구는 실제 Storage·Edge·DB에서 한 번도 돌지 않았다.** 작업방은 파일만 썼고, 로컬의 가짜 응답(네트워크 없음)으로만 돌려 봤다. 가짜 응답은 실제 동작을 대신하지 않는다. SQL 두 파일은 실행도 문법 확인도 하지 못했다.

대상은 **시험 프로젝트 `hmncdheiwqwekdbtijar`뿐**이다. 운영(`qpqjevecjejvbeuogtbx`)에는 아무것도 보내지 않는다. 이 실측은 "중계가 이 크기의 PDF를 범위 요청으로 나를 수 있는가, 표시 시간이 얼마나 느려지는가, 로그인 종료 뒤 거절되는가"만 본다. 실제 책 중계(계약 5)가 아니다.

## 통과 기준 (계약에서 고정 — 측정 화면이 계산해 `verdict`에 적는다)

필수 판정 대상은 **160MB·68MB** 두 크기다. 34MB는 같은 표에 적되 판정에 넣지 않는다(참고 측정).

| 항목 | 기준 |
|---|---|
| 표시 시간 | 필수 크기별·열기 유형별("첫 요청" / "같은 주소로 다시 요청")로 D·R 각각 5회의 **중앙값**을 견준다. R − D가 첫 쪽 **+1초 이내**, 중간·끝 쪽 **+0.5초 이내**. 두 열기 유형 모두 만족해야 한다. 최댓값도 함께 적힌다 |
| 표시 실패 | 0 |
| 잘못된 범위·바이트 | 0 |
| 종료 뒤 | 같은 주소·새 주소의 `GET`·범위 요청(앞·중간·끝)·`HEAD`가 **전부 401 또는 403이고 보호 본문 0바이트**. 미확인이 하나라도 있으면 통과 아님 |

D = 직접 Storage, `apikey`·`Authorization` 둘 다 **공개 키**(지금 학생 화면의 방식). R = 중계 함수, `apikey` 공개 키 + `Authorization` **살아 있는 시험 회원 자격**. "직접 경로 + 회원 자격"은 성능 비교에 넣지 않고 별도 진단으로만 적힌다.

이 기준은 **후보 선정 기준이지 운영 보장이 아니다.**

### 전송량 어림 (0-5에 쓴다. 작업방의 계산 — 실제 값이 아니다)

파일 셋의 합은 263.8MB(160.7 + 68.7 + 34.4)다. PDF.js는 문서를 열면 필요한 구간을 받으면서 **파일 전체도 뒤에서 계속 받는다**(작업방의 로컬 점검에서, 세 쪽을 그리는 동안 160MB 전체를 받았다). 측정이 끝나면 닫으므로 실제로는 회선 속도에 따라 그보다 적다. 아래는 "열 때마다 전체를 받는다"는 최악값이다.

| 단계 | 직접(D) — Storage가 브라우저로 | 중계(R) — 함수가 브라우저로 | 중계(R) — Storage가 함수로 |
|---|---|---|---|
| 올린 뒤 구간 대조(`upload.mjs`) | 약 7MB | — | — |
| 2. 범위 응답 대조(범위 없는 `GET` 전체 포함) | 약 274MB | 약 274MB | 약 274MB |
| 3. 표시 시간(크기 셋 × 열기 유형 둘 × 5회 = 경로마다 30번 열기) | 최악 약 2,640MB | 최악 약 2,640MB | 최악 약 2,640MB |
| 4. 종료 뒤 시험 · 5. 캐시 머리글 | 1MB 미만 | 약 15MB | 약 15MB |
| **합** | **최악 약 2.9GB** | **최악 약 2.9GB** | **최악 약 2.9GB** |

- 올리기 263.8MB는 받는 쪽 전송이다(나가는 전송량이 아니다).
- 함수가 Storage에서 받아 오는 양(셋째 열)이 전송량으로 과금되는지는 **작업방이 확인하지 못했다.** 중단선을 볼 때는 넣어서 센다: **최악 약 8.7GB**. 34MB를 빼면(`측정 화면의 체크 해제`) 약 7.6GB.
- 줄이는 방법(통과 기준은 그대로): 2단계의 "범위 없는 GET을 끝까지 받는다"를 끄면 약 0.8GB가 준다 — 그러면 범위 없는 `GET`의 길이·내용은 **미확인**으로 적힌다.
- 측정 중에 전송량이 어림을 넘는 것으로 보이면(사용량 화면) 측정 화면의 "멈추기"를 누르고 멈춘다.

- 올리다 끊기면 이 실행 안에서 받은 위치부터 잇는다. 프로세스가 죽었으면 `upload.json`의 그 객체가 `started`로 남는다 — 같은 명령에 `--adopt`를 붙이면, 그 이름의 객체가 있을 때 크기와 구간 대조로 확인해 받아들인다(없으면 처음부터 다시 올린다).

- 측정 중에 끝내지 않는 로그인의 자격이 2분 아래로 남으면 측정 화면이 멈춘다. 같은 로그인으로 새 자격을 받아(새로 고침) 입력 칸에 넣고 "이어 하기"를 누른다.

## 4단계 — 임시 SQL up

**임시 SQL 직전 대상 확인(4-1)을 한다. 다르거나 확인할 수 없으면 4-2를 실행하지 않는다.** `set b2n3.test_project_ref`는 실제 연결 대상을 증명하지 못한다 — DB는 자기 프로젝트 ref를 스스로 알지 못한다.

| 순서 | 보낼 요청 | 기대 | 변화 |
|---|---|---|---|
| 4-1 | **SQL 통로의 대상**: 통로가 가리키는 프로젝트의 ref를 다시 확인하고 ㉮를 실행 | ref가 `hmncdheiwqwekdbtijar`. ㉮: `whoami_functions` 0, `zz_b2n3_objects` 3, `all_objects` 3 | 없음 |
| 4-2 | SQL: `set b2n3.test_project_ref = 'hmncdheiwqwekdbtijar';` + `zz_b2n3_up.sql` 전체(같은 요청) | 오류 없음. 마지막 결과: `done` "created …", `anon_can_execute` false, `authenticated_can_execute` true, `service_role_can_execute` false, `public_can_execute` false | 함수 1개 |
| 4-3 | 확인(읽기 요청 둘, PowerShell): `POST $env:B2N3_URL/rest/v1/rpc/zz_b2n3_whoami`, 머리글 `apikey: <공개 키>`, `Content-Type: application/json`, 본문 `{}` — (가) `Authorization: Bearer <끝내지 않는 로그인의 자격>` (나) `Authorization: Bearer <공개 키>` | (가) 200이고 본문이 **3-2에서 만든 회원번호**(따옴표로 싼 글자). (나) 200이 아님(권한 없음) | 없음 |

- 4-2가 "표식 없는 객체가 N개 있다"로 멈추면 시험 프로젝트의 시작 상태가 아니다(또는 대상이 틀렸다) — 아무것도 만들지 않은 것이다.
- 4-3 (가)가 404(함수를 찾지 못함)면 REST 통로가 새 함수를 아직 읽지 못한 것이다. 잠시 뒤 다시 본다.

## 5단계 — 임시 Edge 함수 배포

배포는 브레인방이 대시보드 통로로 한다. **대상 프로젝트 ref `hmncdheiwqwekdbtijar`, 함수 이름 `zz-b2n3-relay`.**

| 순서 | 할 일 | 기대 | 변화 |
|---|---|---|---|
| 5-1 | 배포 대상 프로젝트의 ref와 함수 목록을 다시 본다 | ref `hmncdheiwqwekdbtijar`, `zz-b2n3-relay` 없음. 함수 환경 값에 `B2N3_`로 시작하는 이름 없음 | 없음 |
| 5-2 | 함수 환경 값 여섯 개를 넣는다(아래 표) | 저장됨 | 환경 값 6 |
| 5-3 | `zz-b2n3-relay/index.ts`를 그대로 올린다. **`verify_jwt` 끔**(판정은 함수 안에서 한다) | 배포됨 | 함수 1개 |
| 5-4 | 확인 요청 셋(아래) | 아래 기대 | 없음 |

| 환경 값 | 뜻 |
|---|---|
| `B2N3_MARKER` | 이 실행의 표식(2-1의 `--marker`) |
| `B2N3_MEMBER_ID` | 시험 회원의 **회원번호**(`public.users.id` — 로그인 계정 번호가 아니다. 4-3 (가)가 돌려준 값) |
| `B2N3_OBJECT_160` · `B2N3_OBJECT_68` · `B2N3_OBJECT_34` | 합성 객체 이름 `zzb2n3_<표식>_160.pdf` · `_68.pdf` · `_34.pdf`(이 모양이 아니면 함수가 돌지 않는다) |
| `B2N3_ALLOWED_ORIGIN` | 측정 화면의 출처. `http://127.0.0.1:8787`(포트를 바꿨으면 그 값. 글자 그대로 같아야 한다) |

- `SUPABASE_URL`·`SUPABASE_ANON_KEY`·`SUPABASE_SERVICE_ROLE_KEY`는 실행 환경이 준다(넣지 않는다). 서비스 열쇠는 함수의 환경 값으로만 쓰이고 응답·로그에 나오지 않는다.
- 함수는 실행 환경의 `SUPABASE_URL`이 정확히 `https://hmncdheiwqwekdbtijar.supabase.co`가 아니면 바깥으로 어떤 요청도 보내기 전에 500 `b2n3: wrong target`으로 끝낸다. 환경 값이 틀리면 500 `b2n3: bad config`.

5-4의 확인 요청(주소 `$env:B2N3_URL/functions/v1/zz-b2n3-relay?doc=34&run=smoke1`, 머리글 `apikey: <공개 키>`):

| 요청 | 기대 |
|---|---|
| `Authorization` 없이 `GET` | **401**, 본문 없음, 응답 머리글 `x-b2n3-judge: no_login_credential` |
| `Authorization: Bearer <끝내지 않는 로그인의 자격>`, `Range: bytes=0-99` | **206**, `Content-Range: bytes 0-99/34408972`, 본문 100바이트, `x-b2n3-judge: allow`, `Cache-Control: private, no-store` |
| `OPTIONS`, 머리글 `Origin: http://127.0.0.1:8787`, `Access-Control-Request-Method: GET`, `Access-Control-Request-Headers: authorization,apikey,range` | 204, `Access-Control-Allow-Origin: http://127.0.0.1:8787` |

500·503·404가 오면 6단계로 가지 않는다(503 = 판정 장애: 함수 로그의 `judge=judge_error:<이유>`를 본다).

## 6단계 — 측정 (브라우저)

1. PowerShell에서 환경 변수(`B2N3_ANON_KEY`·`B2N3_JWT_KEEP`·`B2N3_JWT_END`)를 넣고 `node serve.mjs --manifest _local/<표식>/manifest.json` (기본 포트 8787).
2. 브라우저에서 `http://127.0.0.1:8787/measure.html`을 연다(**`127.0.0.1`로** — `localhost`로 열면 출처가 달라 함수의 CORS에 막힌다).
3. **이 탭을 화면 맨 앞에 두고 잰다.** 뒤에 있는 탭은 화면 갱신이 초당 1번으로 느려져 표시 시간이 1초 단위로 뭉개진다(작업방의 점검에서, 자동화 도구가 뒤에서 연 탭이 "보임"으로 보고하면서도 그랬다). 측정 화면은 측정마다 앞뒤로 화면 갱신 간격을 직접 재서, 느리면 재지 않고 "멈춤: 화면 갱신이 느리다"로 기다린다. 느린 채 끝난 측정(`frames_slow`)은 판정에 쓰지 않는다 — 탭을 앞에 두고 "표시 시간 측정 시작"을 다시 누르면 그것만 다시 잰다.

| 순서 | 화면에서 | 기대 | 멈추는 조건 |
|---|---|---|---|
| 6-0 | "자격 확인" | "확인함"과 회원 계정·두 `session_id`·남은 시간 | 어긋남이 적히면 요청 0으로 멈춘 것이다 |
| 6-1 | "로컬 원본 확인"(Supabase 요청 0) | 세 크기 모두 "맞음", 쪽수 344·246·292 | 실패하면 합성 PDF나 PDF.js 문제다 — 뒤 단계를 하지 않는다 |
| 6-2 | "범위 응답 대조 시작" | 크기·경로마다 구간 8/8, `HEAD` 200, 범위 없는 `GET` 200이고 길이·sha256 일치, **어긋남 0** | 어긋남이 있으면 무엇인지 기록(통과 아님). D의 `Content-Range`·`Accept-Ranges`가 "관측 불가"면 Storage가 그 머리글을 브라우저에 노출하지 않는 것이다 — 그대로 기록한다 |
| 6-3 | "표시 시간 측정 시작" | 60번 열기(크기 3 × 열기 유형 2 × 5회 × 경로 2)가 끝나고 표에 중앙값·최댓값·R−D·판정 | 표시 실패는 오류 문구와 함께 적힌다(통과 아님). 중간에 멈추려면 "멈추기" |
| 6-4 | 결과가 `_local/<표식>/results/b2n3_<표식>_<세션>.json`에 저장됐는지("저장됨: …") | 저장됨 | 저장 실패면 "JSON 내려받기" |

- 한 번의 측정: **첫 쪽** = 문서 열기 시작 → 1쪽 렌더 완료. **중간·끝 쪽** = 이미 열린 그 문서에서 이동 시작 → 렌더 완료(쪽마다 새로 열지 않는다). 그 쪽에서 글자를 뽑아 쪽 번호·표식이 맞는지 본다. D·R 모두 같은 화면 크기(1000×760 영역)·같은 배율(맞춤 배율 × 1.0).
- 열기 유형: **"첫 요청"**(`first`) = 주소에 매번 새 `run` 값 / **"같은 주소로 다시 요청"**(`again`) = 그 조건의 첫 요청 1회차 주소를 다시 쓴다. 두 유형의 시간은 합치지 않는다.
- **`run` 값을 바꿨다는 것만으로 "캐시를 피했다"고 읽지 않는다.** 측정마다 `resource`(Resource Timing: 요청 수, 전송 바이트, 캐시에서 왔는가)와 8단계의 캐시 머리글을 함께 본다. 교차 출처 응답은 서버가 허용하지 않으면 전송 바이트가 0으로 보인다 — 그때는 `sizes`에 "브라우저에서 관측 불가"로 적히고 `from_browser_cache`는 null이다(0이나 "캐시 아님"으로 읽지 않는다).
- `pdfjs_progress`는 PDF.js가 센 받은 바이트다(어림). 전송량의 정본은 로그다(8단계).

## 7단계 — 종료 뒤 시험

끝낼 로그인의 자격을 7단계 직전에 새로 받았으면 입력 칸에 넣고 "자격 확인"을 다시 누른다.

| 순서 | 누가 | 할 일 | 기대 | 변화 |
|---|---|---|---|---|
| 7-1 | 화면 | "(1) 종료 전 대조군" — 끝낼 로그인의 자격으로 R에 `GET`·범위 요청 셋·`HEAD` | 전부 성공(200/206, 받은 바이트가 원본과 같음). 화면에 끝낼 `session_id`가 나온다 | 없음 |
| 7-2 | 브레인방 | **그 로그인만** 로그아웃: `POST https://hmncdheiwqwekdbtijar.supabase.co/auth/v1/logout?scope=local`, 머리글 `apikey: <공개 키>`, `Authorization: Bearer <끝낼 로그인의 자격>` (2a에서 204로 확인된 형식) | 204 | 그 로그인 기록 1행이 사라짐 |
| 7-3 | 브레인방 SQL(읽기) | ㉯ | **`end_session` 0, `keep_session` 1** | 없음 |
| 7-4 | 화면 | "(2) … 확인했다"에 표시하고 "(3) 종료 뒤 요청 + 같은 때의 대조군". **자격 입력 칸은 바꾸지 않는다**(이미 받아 둔 같은 자격으로 다시 요청하는 것이 시험이다) | 아래 | 없음 |

7-4의 기대:
- 종료 뒤(끝낸 로그인의 자격): **같은 주소**(7-1에 쓴 주소)와 **새 주소** 각각의 `GET`·범위 요청(앞·중간·끝)·`HEAD`가 전부 **401**(`x-b2n3-judge: not_member`), 받은 바이트 0. 크기 셋이면 30건.
- 같은 때의 대조군(끝내지 않은 로그인의 자격): 같은 파일이 열린다(200/206, 바이트 일치) — 그래야 거절이 "그 로그인이 끝나서"임이 확인된다.
- 직접 경로 + 회원 자격(진단): 시험 프로젝트의 `books`에는 로그인 역할 읽기 규칙이 없어 끝낸 로그인·끝내지 않은 로그인 **둘 다 처음부터 거절**일 수 있다 — 그러면 그렇게 기록한다(판정에 넣지 않는다).
- 화면의 판정: `pass`(전부 거절 + 대조군 열림) / `fail`(하나라도 200·206이거나 본문이 왔다) / `unverified`. **네트워크·CORS 오류·시간 초과·503(판정 장애)은 거절 성공이 아니라 미확인이다.** `HEAD`는 상태로 판정한다(길이만 보지 않는다). 401/403이라도 `x-b2n3-judge` 머리글이 없으면(함수가 낸 응답인지 확인하지 못하면) 미확인으로 둔다.
- 7-1이 성공하지 못했으면 7-2로 가지 않는다(로그아웃하지 않는다).

## 8단계 — 캐시 머리글과 로그

| 순서 | 할 일 | 기대 |
|---|---|---|
| 8-1 | 화면: "캐시 머리글 확인"(측정이 다 끝난 뒤에) | "같은 주소로 다시 요청"에 쓴 주소마다 `Cache-Control`·`cf-cache-status`·`Age`(보이는 만큼). R은 `private, no-store` |
| 8-2 | 화면: "결과 저장" | 저장됨. 결과 JSON의 `verdict` |
| 8-3 | **중계 쪽 요청 수·전송량**: 함수 `zz-b2n3-relay`의 로그에서 이 측정의 줄을 센다 | 아래 |
| 8-4 | **직접 쪽 요청 수·전송량**: Storage(API 게이트웨이) 로그에서 `run` 값으로 센다 | 아래 |

- 함수 로그는 요청마다 한 줄이다: `b2n3 marker=<표식> run=<요청 꼬리표> doc=<160|68|34> m=<GET|HEAD> range=<받은 Range 또는 -> judge=<판정> status=<상태> bytes=<전달 바이트> ms=<걸린 시간> end=<done|client_closed|upstream_error|none>`. 자격·열쇠는 없다.
- `run` 값은 `<세션>-<꼬리표>-<번호>` 모양이고 세션은 결과 JSON의 `session`이다. 꼬리표: `t160D`·`t160R`(표시 시간), `rg…`(범위 응답 대조), `out…`(종료 뒤 시험).
- 세는 법: 로그 화면에서 `run=<세션>-` 으로 걸러 줄 수와 `bytes=`의 합을 낸다. 내려받은 로그 파일이 있으면 PowerShell로: `Select-String -Path <파일> -Pattern 'b2n3 marker=\S+ run=(\S+) doc=(\d+) .*? status=(\d+) bytes=(\d+)' -AllMatches` 로 뽑아 `run`의 꼬리표별로 더한다.
- **함수 로그는 10초에 100건을 넘으면 빠질 수 있다**(문서의 한도). PDF.js는 한 번 열 때 범위 요청을 수십~수백 건 보낸다(작업방의 로컬 점검에서 160MB 한 번에 300건쯤). 로그의 줄 수가 결과 JSON의 그 측정 `resource.requests_seen`보다 적으면 로그가 빠진 것이다 → **그 요청 수·전송량은 미확인**으로 적는다(로그의 값을 그대로 쓰지 않는다).
- 직접 경로: 로그에서 주소의 `run=` 값이 보이는지 먼저 확인한다. **`run`을 식별할 수 없으면 직접 경로의 요청 수·전송량은 0이 아니라 "미확인"이다.**
- 브라우저의 `resource.requests_seen`에는 사전 요청(`OPTIONS`)이 들어 있지 않다.

| `verdict.result` | `pass` / `fail`(기준 미달) / `not_decided`(아직 다 재지 않았거나 미확인이 남음). `verdict.reasons`에 이유 |
| `verdict.timing` | 조건(크기·열기 유형·쪽)마다 D·R의 5회 원값·중앙값·최댓값·실패 수, R−D, 기준, 판정. 34는 `required_for_verdict: false` |
| `timing.runs` | 60번의 측정 원값(`ms.open`·`first`·`mid`·`last`, 오류 문구, `resource`, `pdfjs_progress`, `frames`) |

| `environment` | 브라우저, 화면 크기·dpr, PDF.js 판, 브라우저가 어림한 회선 |

## 이 실측의 한계 (결과를 읽을 때 함께 적을 것)

- **합성 PDF의 구조가 운영 파일과 다를 수 있다.** 운영 파일은 열어 보지 않았다. 합성 파일은 선형화하지 않았고, 상호 참조표가 파일 끝에 있고, 쪽 목록이 파일 앞의 한 객체에 있으며, 쪽마다 글자 두 줄과 압축하지 않은 회색 그림 하나뿐이다. 운영 파일이 선형화돼 있거나 쪽 자료가 다르게 놓여 있으면 PDF.js가 보내는 범위 요청의 수와 위치가 달라진다.
- **한 기기·한 회선·한 시각**의 값이다. 학생의 기기·회선(특히 휴대 기기)은 재지 않았다.
- **판정은 실제 책 자격이 아니라 회원 판정 1회**(`zz_b2n3_whoami`)다. 계약 5의 판정(책 권한·책 연결 자격)은 더 무거울 수 있다.
- **동시에 여러 학생이 여는 경우는 재지 않았다.** 한 번에 한 문서만 연다.
- **34MB는 참고 측정**이다(통과 기준에 넣지 않는다).
- 중계 함수는 사전 요청(`OPTIONS`) 응답에 유효 시간을 주지 않는다. 사전 요청의 수와 캐시는 브라우저에서 볼 수 없다 — D와 R의 차이에 사전 요청 시간이 섞여 있다.
- 만료된 자격을 중계에 보내면 REST 통로가 판정 함수를 부르기 전에 거절하고, 함수는 그것을 **판정 장애(503)**로 낸다(계약의 구분: RPC가 정상 응답한 경우만 자격 거절). 종료 뒤 시험은 만료되지 않은 자격으로 한다.
- 표시 시간의 끝은 `page.render`가 끝난 때다. 뷰어가 그 뒤에 하는 링크 겹침 등은 넣지 않았다.
- 전송량: 브라우저는 교차 출처 응답의 바이트를 보여 주지 않을 수 있다. 로그가 빠지거나 `run`을 식별할 수 없으면 미확인이다.
