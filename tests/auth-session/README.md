# 공홈 인증 모듈 격리 시험 (보안작업 묶음2 계약 3A)

`js/auth-session.js`(새 로그인 스위치·인증 모듈)가 꺼져 있을 때 아무것도 하지 않는지, 켜져 있을 때 기존 요청의 자격과 기존 로그인 상태를 건드리지 않는지 본다. 기준 커밋은 `d39c0ee`.

## 두 가지

1. **회귀시험 `run.mjs`** — 전부 가짜(가짜 화면·가짜 저장소·가짜 시계·가짜 서버). 실제 네트워크 요청 0건. 작업방이 돌린 것은 이것뿐이다.
2. **화면 시험 `serve.mjs` + `절차.md`** — 브레인방이 시험 프로젝트(`hmncdheiwqwekdbtijar`)로 실제 브라우저에서 확인할 때 쓴다. 작업방은 실행하지 않았다(가짜 키로 서버가 뜨고 파일을 내주는 것까지만 127.0.0.1 안에서 확인).

가짜 화면에서 통과한 것은 실제 브라우저·실제 서버에서 된다는 증거가 아니다.

## 회귀시험 실행

저장소 폴더에서, Node v26. 설치할 것은 없다.

```
node tests/auth-session/run.mjs
```

통과하면 마지막 줄이 `결과: 통과`, 종료 코드 0. 하나라도 어긋나면 `결과: 실패`, 종료 코드 1.

보는 것:

- 계약 1 회귀시험(`tests/supabase-config-headers/`)을 다시 돌린다 — 비교 1,620건·요청 1,458건·차이 0. 그 시험의 기준 파일(`8bddea5`)이 `d39c0ee` 의 것과 같은지도 본다.
- 글자: 저장소의 스위치 값이 꺼짐, 스위치를 켜는 길이 값 비교 한 줄뿐, 기준에서 바뀐 파일의 범위, 인증 모듈을 싣는 화면(`index.html`·`login.html`), 헤더 함수에 등급을 넘기는 호출 0.
- 꺼짐 × 저장소 상태 다섯(빈 브라우저 / 옛 학생 / 교재 편집만 / 후속메일만 / 섞임+만료) × 화면 동작 13가지(index 열기, login 열기, login 제출 9가지, 로그아웃 2가지)를 기준의 파일로 돌린 기록과 대조 — 요청의 주소·메서드·머리글·본문, 저장소 접근의 순서와 값, 화면 이동, 안내, 콘솔.
- 기존 래퍼 요청: 계약 1 의 입력 1,620건을 화면 안에서 그대로 불러 기준과 대조 — 꺼짐, 켜짐(로그인 전·확인됨·거절) × 저장소 상태 다섯.
- 켜짐의 인증 동작(가짜 로그인 서버, SDK 사본은 실제 파일): 로그인 성공 하나, 주소의 로그인 정보, 복원, signed_in 이 되지 않는 12가지, 만료·종료, 로그아웃, 옛 값이 있는 브라우저, 자격을 싣는 조건(비슷한 주소 19가지·리디렉션), 복원 중·거절 뒤, 관리자 표시, 두 탭.
- 감도: 일부러 바꾼 사본 33개를 시험이 잡는지.
- 화면 시험용 서버의 몸통을 소켓 없이: 내줄 수 있는 모든 파일을 꺼짐·켜짐으로 한 번씩(운영 흔적이 남은 채 내주는 것 0), 자동화용 "보내기 전에 가르기".

## 파일

- `run.mjs` — 회귀시험. `world.mjs` — 파일 묶음(기준·작업본·내줄 사본)과 가짜 세계. `browser.mjs` — 가짜 브라우저. `fake-supabase.mjs` — 가짜 로그인 서버.
- `rewrite.mjs` — 내줄 때 바꾸기(주소·공개 키 → 시험 프로젝트, 스위치)와 운영 흔적 찾기. 서버와 회귀시험이 같이 쓴다.
- `serve.mjs`·`serve-core.mjs` — 화면 시험용 로컬 서버(127.0.0.1). `request-log.mjs` — 자동화가 쓰는 "보내기 전에 가르기"와 가린 기록.
- `절차.md` — 브레인방의 화면 시험 순서와 세는 법.

## 지키는 것

- 저장소의 스위치 값은 꺼짐이다. 켜는 길은 `serve.mjs --mode on` 이 내주는 사본뿐이다(저장소의 파일은 바꾸지 않는다).
- 가짜 서버의 계정·JWT 모양의 값은 전부 지어낸 것이다. 출력에서 JWT 모양과 공개 키는 가린다.
- 계약 1 회귀시험은 "헤더 함수의 이름을 쓰는 다른 파일"을 찾는다. 그래서 이 폴더의 파일은 그 이름을 글자 그대로 적지 않는다(`run.mjs` 는 이어 붙여 쓴다).
